<p>给客户做 Claude 演示，最怕的不是功能讲不清楚，而是演示到一半页面要求重新验证，或者切换账号后地区跳了、语言变了，现场解释都来不及。这类事故基本都能在时间轴上提前排掉。下面按演示前七天、开通后第一小时、演示前一天、当天、以及结束后 24 小时五个节点展开，每个节点写清要做的动作和判断标准，照着走一遍，临时出岔子的概率会明显下降。</p>

<h2>一、演示前七天：把地区固定下来</h2>
<p>地区是整条链上最早决定、也最难临时改的一项。同批演示用的账号最好走同一个国家甚至同一个城市，这样客户看到的界面语言、时间显示、可选服务都一致。</p>
<h3>按客户所在地和语言选，而不是按价格选</h3>
<p>客户是北美团队，走美国住宅地址最自然；客户在东南亚但内部工作语言是英语，走新加坡或美国都可以，但整批要统一。选定之后写进演示方案，明确"所有演示账号出口均为某国某城"，避免中途有人觉得另一条线更快就擅自换掉。</p>
<h3>提前确认地址的机构字段</h3>
<p>拿到线路后跑一次 <code>whois 地址</code>，确认机构名是当地的宽带运营商而不是托管商。再确认时区：美国东部住宅地址配 <code>America/New_York</code>，西部配 <code>America/Los_Angeles</code>，和出口所在地对上，浏览器里不要留系统默认的东八区。</p>

<h2>二、开通后第一小时：线路落地要做的三件事</h2>
<p>线路到手不等于环境就绪。第一小时的目标是让"哪条线服务哪个号"这件事变成可查的事实，而不是记在脑子里。</p>
<h3>逐条验证出口，别信面板显示</h3>
<p>每条线单独启用后，访问一个查询 IP 的页面，把返回的地址、地区、ASN 抄进表格。面板上写"美国"不代表实际落地在美国，中间经过中转时出口可能落在别处。十条线全部验证一遍，通常十几分钟。</p>
<h3>给每个账号配独立的浏览器配置文件</h3>
<p>用浏览器自带的多配置文件功能，一个配置文件对应一个演示账号、一条线路。命名规则建议"国家-城市-序号"，比如 <code>us-lax-01</code>，和台账一一对应，演示当天不用现找。</p>
<h3>先把登录跑通，再谈演示内容</h3>
<p>第一小时不测业务功能，只测登录：能不能进、要不要额外验证、进去之后会话能保持多久。这一步过了，后面的准备才有意义；过不了就立刻换线，别拖到演示前一天。</p>

<h2>三、演示前一天：完整预演一遍</h2>
<img src="/tp.png" alt="Claude 演示前按时间节点检查出口地区一致性流程">
<p>预演的价值在于暴露"只有完整走一遍才会出现"的问题，比如某个账号的订阅状态在换线后需要重新确认，或者共享屏幕时字体渲染不一样。预演要按演示当天的顺序完整跑，不要跳步。</p>
<h3>用真实流程跑一遍，计时</h3>
<p>从登录第一个账号开始，到切换第二个账号、展示对话、导出结果，全程计时。把每一步的耗时记下来，第二天安排演示节奏时按这个时间再加三成余量。超过预期的环节单独标注，想好简化的说法。</p>
<h3>准备一条备用线路</h3>
<p>备用线不等于"再买一条"。它可以是同地区另一条已配置好的地址，也可以是提前登录好、保持会话的第二个浏览器配置文件。关键是切换动作要在一分钟内完成，且切换后地区不变。</p>

<h2>四、演示当天：从开场前十五分钟到结束</h2>
<p>当天的原则是"不改配置"。任何临时调整都会引入未验证的变量，出问题时也无法判断是配置导致的还是内容导致的。</p>
<h3>开场前十五分钟做三件小事</h3>
<p>第一，逐个配置文件打开一次，确认登录态还在；第二，查一次出口地址，确认与台账一致；第三，把不需要的浏览器标签、通知、即时通讯软件全部关掉，避免共享屏幕时弹出与演示无关的窗口。</p>
<h3>演示中不要切换地区</h3>
<p>即使某个账号的反应慢，也不要临时切到另一国的线路去"试试"。地区跳变带来的验证弹窗，比慢两秒严重得多。真要换，换的是备用线里同地区的那条。</p>
<h3>真弹出验证页时怎么接话</h3>
<p>如果还是弹出了验证，直接说明"这是平台对新环境的例行确认，我们提前准备了备用环境"，然后切到备用配置文件继续。客户更在意你能不能稳住流程，而不是这一次弹窗本身。</p>

<h2>五、收尾 24 小时：补记录，再把清单打勾</h2>
<p>演示结束当天趁记忆还新鲜把记录补齐，这份记录是下次演示的起点。应急时做过的简化，如果效果好就写进标准流程；只是权宜的，标明"仅本次适用"，别让下次把它当惯例。</p>
<h3>把预演工时和实际用时并排记</h3>
<p>标出偏差超过两成的环节，异常点写清时间、账号、表现、处置方式，不写"感觉有点卡"这类描述。这份偏差表能直接告诉你下一场该多留多少余量。</p>

<h2>常见问答</h2>
<h3>同批账号必须走同一个城市吗？</h3>
<p>答：同一国家是底线，同一城市更稳。跨国会让界面语言和可用服务出现差异；跨城市虽然多数情况没问题，但如果客户会看登录记录或时区显示，城市不一致仍然是一个需要解释的点。</p>
<h3>演示中途真的不能换线吗？</h3>
<p>答：不能换地区，但可以换同一地区的另一条线。前者会触发重新验证，后者对平台来说只是同一地区内的地址变化，影响小得多。备用线要提前配好并保持登录，现场才有得换。</p>
<h3>共享屏幕时会不会暴露代理设置？</h3>
<p>答：如果只在浏览器层配置，系统设置里看不到；如果用系统级客户端，注意不要把客户端窗口或托盘提示共享出去。演示前把相关窗口最小化，是成本最低的做法。</p>
<h3>客户要求看后台数据，需要额外准备什么？</h3>
<p>答：后台类页面通常对登录环境更敏感。建议提前用一个专门的演示账号把后台各页面点一遍，确认没有二次验证；同时把需要展示的数据提前导出成文件，减少现场实时查询的次数。</p>
